# CIM Lab 6: Diffusion posterior sampling for inverse problems

Last week you solved inverse problems with hand-designed priors (Tikhonov, TV). This week the prior is a **pretrained diffusion model**, and we use **diffusion posterior sampling (DPS)** ([Chung et al., ICLR 2023](https://arxiv.org/abs/2209.14687)) to draw samples from $p(x \mid y)$ for super-resolution, deblurring, inpainting and colourisation.

As in Labs 3–5, there is one Hydra experiment file (`conf/experiment.yaml`) and a small package. Change the config or override values on the command line; read and edit a few short functions.

## Learning outcomes

By the end, you should be able to:

1. explain each step of the DPS algorithm and where the prior and the likelihood enter;
2. describe how the guidance term, guidance weight and number of steps affect the result;
3. find inverse problems and images where DPS works well and where it fails, and explain why;
4. quantify reconstruction quality with distortion, perceptual, data-consistency and uncertainty metrics, and explain where they disagree;
5. design and run a hyperparameter search with a validation/test protocol, and justify its choices.

## DPS in one slide

The diffusion model is trained on clean images. It gives us a denoiser $D(x_t, t)\approx \mathbb E[x_0\mid x_t]$ (Tweedie's formula), and therefore the prior score $\nabla \log p_t(x_t)$. For the posterior we also need the likelihood score $\nabla_{x_t}\log p(y\mid x_t)$, which is intractable. DPS approximates it by pretending $x_0$ equals the denoiser's estimate:

$$
\nabla_{x_t}\log p(y\mid x_t) \approx \nabla_{x_t}\log p\big(y \mid x_0 = D(x_t,t)\big).
$$

Each iteration of `dps()` therefore:

1. computes $\hat x_0 = D(x_t, t)$;
2. takes an ordinary (unconditional) DDPM/DDIM step $x_t\to x_{t-1}$ using $\hat x_0$;
3. **guides** it: $x_{t-1} \leftarrow x_{t-1} - \zeta\, \nabla_{x_t} \mathcal L\big(y - A(\hat x_0)\big)$, differentiating *through the denoiser*.

The paper uses $\mathcal L = \|y - A\hat x_0\|$, the norm rather than the squared norm, with $\zeta=1$ for super-resolution. That is `guidance: dps`, `weight: 1.0`.

## Part C: guidance terms

`guidance_loss()` in `dps.py` implements four likelihood surrogates:

| `sampler.guidance` | loss $\mathcal L$ | idea |
| --- | --- | --- |
| `dps` | $\lVert r\rVert$ | the paper; the step size is effectively $\zeta / \lVert r\rVert$ |
| `squared` | $\tfrac12\lVert r\rVert^2$ | the Gaussian log-likelihood with unit variance |
| `annealed` | $\lVert r\rVert^2 / 2(\sigma_y^2+\sigma_t^2)$ | variance grows with the diffusion noise level |
| `none` | 0 | the prior only |

Here $r = y - A(\hat x_0)$. These terms put `weight` on **very different scales**, so comparing them at the same weight is unfair. Find a good weight for each term before comparing them. Which is most robust to the choice of weight and to the noise level `operator.noise.sigma`?

**Task:** implement `guidance: custom`. Ideas:

- a time-dependent weight, e.g. weak guidance early and strong guidance late, or the reverse;
- normalising the gradient so every step has the same size;
- guidance only during the last part of sampling;
- the exact Gaussian likelihood with the true $\sigma_y$.

Explain why your idea should help, then test it.

To compare against a library implementation, run DeepInverse's own sampler with `sampler.name=deepinv` (`guidance` `dps` or `annealed`). Note that its `weight` uses a different scale.

## Part F: quantifying accuracy

`metrics.json` reports:

| metric | meaning |
| --- | --- |
| `psnr_sample`, `ssim_sample` | distortion of individual samples (higher is better) |
| `psnr_mean` | distortion of the posterior mean |
| `lpips_sample`, `lpips_mean` | perceptual distance, from a learned feature space (lower is better) |
| `residual_over_noise` | RMS of $y - A\hat x$ divided by $\sigma_y$; the ideal is about 1 |
| `mean_std` | average posterior standard deviation (uncertainty) |
| `std_error_corr` | correlation between per-pixel std and error: is the uncertainty useful? |
| `psnr_baseline` | the pseudo-inverse $A^\dagger y$, for reference |
| `seconds` | sampling time per image |

- Find a case where PSNR and LPIPS disagree about which configuration is better. Which would you trust, and for what application? Search for the *perception–distortion trade-off*.
- Why can a sample have a lower PSNR than the blurry pseudo-inverse and still be a "better" reconstruction?
- Metrics on one image are noisy. How many images and seeds do you need before a difference is real?

## Part G: hyperparameter search

Parts B–D showed that the best `weight`, `num_steps`, `eta` and `guidance` depend on one another and on the task. Tuning them one at a time by hand is slow and misses those interactions. In this part you build a small **hyperparameter search**, the same workflow used to tune any ML system:

1. define a **search space**: which settings, and over what ranges;
2. generate **candidate configurations**, by random or grid search;
3. score each candidate with an **objective** on **validation** images;
4. **confirm** the most promising candidates, because the single best score is partly luck;
5. report the chosen configuration once, on held-out **test** images.

The settings are in `conf/optimise.yaml`. It extends `experiment.yaml`, so the task (`operator`, noise, model) comes from there. The code is in `src/cim_lab_6/optimise.py`, and step 5 plus the bookkeeping are provided. Run it with:

```powershell
uv run python -m cim_lab_6.optimise
uv run python -m cim_lab_6.optimise operator.name=inpainting_box search.strategy=grid
```

It writes `trials.csv` (every configuration and its scores), `trials.png` (the objective against each hyperparameter) and `report.yaml` (the chosen settings against the default, on test images).

Check each task with `uv run pytest tests/test_optimise.py`. Keep notes of your decisions and why you made them: they are the point of this part.

**Task 1: the search space** (`space:` in `conf/optimise.yaml`). The starter space contains a single weight, so it searches nothing. Decide which sampler settings to search, and over what ranges. Use your Part B–D results.

- Why should `weight` be searched on a log scale?
- Each extra hyperparameter multiplies the size of a grid. Which settings are worth the cost?
- Is `num_steps` a hyperparameter to optimise, or a budget you fix in advance?

**Task 2: generating candidates** (`sample_value()` for random search, `grid_values()` for grid search).

- How many runs would a grid over your space need? How many random trials could you afford in the same time?
- Read [Bergstra and Bengio (2012)](https://jmlr.org/papers/v13/bergstra12a.html), Figure 1. Why does random search often beat grid search when only a few hyperparameters really matter? Does `trials.png` suggest that only a few matter here?

**Task 3: the objective** (`objective()`, plus `objective:` in the config). Reduce the per-image metrics to one number.

- Which metric matters for your task: PSNR, LPIPS, data consistency, or a combination? Recall Part F.
- Should you take the mean over images, or the worst image?
- How do you enforce the time budget?
- Would a radiologist, a photo app and a forensic analyst choose the same objective?

**Task 4: confirming the winner** (`confirm_top_k()`). During the search each configuration is scored with one seed and few samples, so the top trial is partly the luckiest. Re-evaluate the top *k* configurations over several seeds and choose the best *mean*.

- Does the ranking change?
- How large is the seed-to-seed standard deviation compared with the differences between configurations?

**Task 5: report and reflect** (`report.yaml`).

- Does your chosen configuration beat the default on the **test** images, and by how much?
- Why must test images never influence any choice? Check `validation` and `test` in the config.
- The validation and test faces are all synthetic, from the model's own prior. Would your conclusions hold for real faces? Try `test: [dinv:celeba_example.jpg, ...]`.
- Optimise for a second task, e.g. `operator.name=motion_blur`. Do the best settings transfer?

**Extensions:** replace random search with [Optuna](https://optuna.org) (`uv add optuna`), which chooses each new trial using the results so far. Or add the parameters of your custom guidance (Part C) to the search space.
